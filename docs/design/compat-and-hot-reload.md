# 互換性レイヤーとホットリロード

## 方針

1 つのプロジェクトを、性質の違う出力先 (Mod、プラグイン、データパック、統合版) と 6 つの Minecraft バージョンへ同時に出力します。各機能は、出力先ごとに次の 3 段階のどれかで扱います。

| 段階 | 意味 | 例 |
| --- | --- | --- |
| 対応 (FULL) | そのまま動く | Mod の独自ブロック |
| 代替 (FALLBACK) | ModStudio が代わりの仕組みを生成して動かす | データパックの独自アイテムをカスタムモデルデータで再現する |
| 非対応 (NONE) | その出力からは除き、理由を表示する | データパックの独自ブロック |

判定は `core/Compat.java` にまとめています。互換性ページ (`ui/pages/CompatPage.java`) は、その結果を要素 × 出力先の表にして表示します。要素ごとの判定のほか、プロシージャの中の手順も調べます。

## 生成時の分岐

プロシージャの「もし」には、生成時に決まる条件が 2 つあります。

- `platform`: mod / forge / neoforge / fabric / paper / datapack / java_code / bedrock
- `mc_version`: 下限と上限 (上限は「指定なし」にもできる)

`ProcCompiler.compileTime()` がこの 2 つを出力先ごとに評価し、一致した側の手順だけを出力します。どちらを選んだかは、`# platform matches ...` という形のコメントで出力に残ります。統合版 (`BedrockGen`) でも同じように評価します。

バージョンの範囲は `McVersion.orNull()` で読みます。「指定なし」は null として扱い、範囲を制限しません。`McVersion.of()` は不明な値を 1.21.1 として返すので、範囲の判定には使いません。

## シム (古いバージョンの代わりの仕組み)

| 機能 | 新しいバージョン | 1.20.1 での代わり |
| --- | --- | --- |
| 関数の引数 | マクロ `$(name)` | スコア `$name <ns>.args` に入れて渡す |
| 乱数 | `random value` | マーカーを召喚し、その UUID[0] を `%=` で範囲に収める |
| サイドバーの動的な行 | 表示名の書式 | 開いたときの値で表示する |
| 「中断」の手順 | `return` | 使えない。残りの手順も実行されるので、問題ページで警告する |
| TNT の導火線 | `fuse` | `Fuse` |

データパックでは、インベントリ GUI をチャットのクリックメニューで代用します。データパックだけでは通信できないので、HTTP リクエストは「失敗」の分岐を実行します。

## ホットリロード

テストプレイ中に編集すると、ゲームを再起動せずにデータを入れ替えます。実装は `gen/LiveData.java` と `ui/pages/PlayPage.java` です。

1. ワークスペースの変更 (`revisionProperty`) を 1.5 秒まとめてから、プロジェクトを生成し直します。
2. 生成したファイルのうちデータの部分を、テスト用ワールドの `datapacks/<ns>_live/` に、ワールドのデータパックとして書き込みます。
   - データの部分とは `data/` 以下のファイルで、ワールド生成は除きます。
3. 出力先によって、次のように反映します。
   - **テストサーバー (Mod)**: 標準入力に `reload` を送ります。
   - **Paper**: `minecraft:reload` を送ります。Bukkit の `/reload` はプラグインごと読み込み直すため使いません。
   - **テストクライアント**: 最後に遊んだワールド (`session.lock` が新しいもの) に書き込み、ゲーム内で `/reload` するよう案内します。
   - **データパック**: ホットリロードが有効なら、zip ではなくフォルダとしてインストールします。ゲームが zip を開いたままにする (Windows ではロックされる) ためです。編集のたびにそのフォルダを書き換えます。
4. Java コード、アセット、ワールド生成のハッシュ (`LiveData.codeHash`) が起動時と変わったときは、再起動が必要だと知らせます。

ワールドのデータパックは Mod やプラグインのデータより後に読み込まれます。そのため、同じパスのファイルは新しい内容で上書きされます。関数タグは重複が除かれるので、同じ関数が 2 回実行されることはありません。古い `_live` パックが新しいビルドの内容を隠さないように、テストを起動するたびに消しています。
