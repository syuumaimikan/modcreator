# 演出・アニメーション・組み立て式機械・データパック

カメラワーク、モデルのアニメーション、メニューの見た目、工具で組み立てる機械、データパックの追加要素 (プレディケート、アイテム修飾子、ダイアログ、取引商人) と、全バージョン共通パックの出力方法をまとめます。どれも Java 版の出力先 (Mod、プラグイン、データパック) で同じ関数を使います。

## カットシーン (カメラワーク)

実装は `gen/CutsceneGen.java` です。

- カメラのキーごとに、時刻、位置、向き (または注視点)、動き方 (なめらか、直線、加速、減速、加減速、カット) を設定します。
- 文字、サウンド、コマンドのイベントを時刻に合わせて流せます。
- 再生の流れ
  1. 見る人をスペクテイターにして、`item_display` のカメラを観戦させます
  2. カメラを毎 tick、あらかじめ計算した経路に沿ってテレポートします (1.20.2 以降は `teleport_duration` でクライアント側も補間)
  3. 終わると元のゲームモードと位置に戻し、`onEnd` の手順を実行します
- フレームの選択は関数の二分木で行うので、長いカットシーンでも 1 tick あたりの判定は数回です。
- スニークで飛ばせます (設定で切り替え)。
- 統合版はカメラコマンドで近い動きを再現します (互換性ページでは「代替」)。

## モデルのアニメーション (Mob と機械)

実装は `core/Rig.java` と `gen/RigGen.java` です。

- 3D モデルにボーン (親子関係とピボット) と、キーフレームのアニメーション (位置、回転、拡大、補間の種類、ループ / 1 回 / 最後で止める) を付けます。
- **Mob**
  - ボーンごとに `item_display` を作り、透明にした Mob に乗せます
  - アニメーションは 2 tick ごとのフレーム関数に展開し、2 tick の補間で動かします
  - 待機、歩き、被ダメージ、攻撃、死亡のアニメーションを状態に合わせて切り替え、手順「アニメーションを再生」でも呼べます
- **組み立て式の機械**: 待機中と稼働中のアニメーションを、機械のディスプレイで再生します。
- ボーンの見た目は、ボーンごとのアイテムモデルとして出力します (1.21.4 より前はカスタムモデルデータ)。

## インベントリ GUI の見た目とアニメーション

実装は `gen/BridgeGen.java`、`gen/InterfaceGen.java`、`gen/AssetGen.java`、`core/MenuArt.java` です。

- **背景**: なし、パネル (色と枠を指定して自動で描画)、自作テクスチャ (行数ごとのテンプレートあり)
  - フォントの文字としてタイトルに埋め込み、リソースパックに `textures/gui/menu/<名前>.png` と `font/menu.json` を出力します
- **開くときのアニメーション**: スロット順、行ごと、列ごと、中央から、の順にアイテムを表示します
- **スロットのアニメーション**: フレームのアイテムを一定間隔で切り替えます
- **サウンド**: 開いたときとクリックしたときの音
- エディタの「アニメーションを再生」で、開くときの動きを確認できます。

## 組み立て式のマルチブロック機械

Immersive Engineering のような、形を作ってから工具で組み立てる機械です。実装は `gen/AssemblyGen.java` です。

1. パターンどおりにブロックを置き、中心のブロックを工具で右クリックすると組み立てます
   - 工具の右クリックは、データパックでは `carrot_on_a_stick` または `warped_fungus_on_a_stick` をもとにしたアイテムで検出します
2. 組み立てるとマーカーとインタラクションエンティティを置き、モデルがあればディスプレイで表示します
3. 入力口の上に投げ込んだアイテムをレシピと照合し、時間とリソース (マナなど) を使って出力口から出します
   - 副産物と確率、レシピごとの処理時間とコストを設定できます
   - 出力口にコンテナがあればそこに入れ、なければその場に落とします
4. 工具で殴ると分解して元のブロックに戻ります
- 組み立て時、使用時、完成時、分解時に、それぞれ手順を実行できます。
- 既存のリソース網 (マナ、エネルギー) から機械に補給できます。

## プレディケート

実装は `gen/PackDataGen.java` です。`data/<ns>/predicate` (1.20.x は `predicates`) に出力します。

- 項目: 確率、天気、時刻、エンティティの状態と種類、効果、装備、スコア、プレイヤーのレベル、乗り物、バイオーム、ディメンション、足元のブロック、明るさ、高さ、別のプレディケート、JSON
- 「すべて満たす」は `all_of`、「どれか 1 つ」は `any_of` に、反転は `inverted` にします。
- バージョンの違い
  - バイオーム: 1.20.5 以降は `biomes` (タグも可)、それより前は `biome`
  - 装備のアイテム: 1.20.5 以降は `items` と `predicates.custom_data`、それより前は `items` のリストと `nbt`
- 使い道: 条件「プレディケートを満たす」、ルートプールの条件、`execute if predicate`

## アイテム修飾子

`data/<ns>/item_modifier` (1.20.x は `item_modifiers`) に出力し、手順「アイテムを修飾」(`item modify entity`) で使います。

- 変更: 個数、耐久値、名前、説明文、エンチャント、ランダムなエンチャント、エンチャント台と同じエンチャント、壊れない、輝き、ポーション、精錬、JSON
- バージョンの違い
  - 説明文: 1.20.5 以降は `mode` (`append` / `replace_all`)、それより前は `replace`
  - エンチャント台と同じ: 1.21 以降は `options` (宝物は `#minecraft:on_random_loot`)、それより前は `treasure`
  - 壊れない、輝き: 1.20.5 以降は `set_components`、それより前は `set_nbt`
  - 複数の変更: 1.20.5 以降は `sequence`、それより前は配列

## ダイアログ

実装は `gen/DialogGen.java` です。

- 形式: お知らせ (ボタン 1 つ)、確認 (はい・いいえ)、複数ボタン (列数を指定)
- ボタンの動作: 閉じる、手順を実行、別のダイアログを開く、Web ページを開く、チャット欄にコマンドを入れる、文字をコピー
- **1.21.6 以降**: `data/<ns>/dialog/<名前>.json` を出力し、`dialog show` で開きます
- **それより前**: 同じ文章とボタンを、クリックできるチャットで送ります (互換性ページでは「代替」)
- 手順を実行するボタンは `/trigger <ns>.dlg set <番号>` を送り、毎 tick の関数が番号に対応する関数を呼びます。OP 権限のないプレイヤーも使えます。
- Paper では、新しいダイアログはサーバーの再起動後に読み込まれます。

## 取引商人

- 村人 (職業、見た目、レベル) または行商人に、決まった取引だけを持たせて `summon` します。
- 取引の値段と商品には、このプロジェクトのアイテムも使えます
  - データパックとプラグインでは、値段は `custom_data` (1.20.5 以降) または `tag` の一部一致で判定し、商品にはすべての見た目を付けます
  - 1.20.5 以降は `count` と `components`、それより前は `Count` と `tag`
- AI なしにするとその場から動かず、職業も変わりません。商人の経験値を 0 にしておくと、レベルが上がって通常の取引を覚えることもありません。

## 全バージョン共通のパック

`gen/Exporter.java` の `universalPack` で作り、`dist/<modid>-<version>-datapack-all.zip` と `-resourcepack-all.zip` に出力します。

- 一番古いバージョンのファイルを土台にします。
- 新しいバージョンごとに、それまでと内容が違うファイルだけを `mc1_21_8` のようなオーバーレイフォルダに入れます。
- `pack.mcmeta` には `supported_formats` と、バージョンごとのオーバーレイ (`overlays.entries`) を書きます。後のオーバーレイほど優先されるので、各バージョンは自分のファイルを読みます。
- 1.20.1 はオーバーレイを読まないので、土台がそのまま 1.20.1 用になります。
- 制限: 古いバージョンにだけあって新しいバージョンにないファイルは、同じ場所を新しいバージョンも読む場合に残ります (フォルダ名が変わった 1.21 以降は影響しません)。
